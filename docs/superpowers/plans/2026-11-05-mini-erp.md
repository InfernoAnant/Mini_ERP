# Mini ERP — Shiv Furniture Works Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build and deploy a Mini ERP covering products, sales, purchase, BoM, manufacturing, place-then-confirm stock operations, MTO procurement, audit logs and a dashboard, with a one-click public demo.

**Architecture:** Express 5 + Prisma API (`server/`) where all business logic lives in `server/src/services`, every stock change is a `StockMove` written inside one Prisma transaction together with its `AuditLog` rows, and product rows are locked with `SELECT … FOR UPDATE`. React + Vite + Tailwind SPA (`client/`) talks to `/api` (Vite proxy locally, Vercel rewrite in production) using an httpOnly JWT cookie.

**Tech Stack:** Node 24, TypeScript 5 strict, Express 5, Prisma 6 + PostgreSQL, Zod 3, jsonwebtoken, bcryptjs, Vitest + Supertest; React 18, React Router 6, Vite 6, Tailwind 3.

**Spec:** `docs/superpowers/specs/2026-11-05-mini-erp-design.md` (read it; this plan argues from it). Brief: `docs/problem-statement.txt`. Rules: `CLAUDE.md`.

## Global Constraints

- TypeScript `strict: true`, no `any` (use `unknown` + Zod). Business logic only in `server/src/services/*`; routes only parse input (Zod), call one service, serialize.
- Stock changes only via `stock.postMoves()` inside a transaction; `Product.onHand` never < 0; free-to-use = on-hand − reserved, computed, never stored.
- Every create / update of tracked fields / delete / status change writes `AuditLog` rows in the same transaction.
- Auth: JWT signed with `JWT_SECRET`, cookie name `token`, `httpOnly`, `sameSite: 'lax'`, `secure` in production, 7-day expiry; payload `{ sub: userId, role }` only (`role` = `'SYSTEM_ADMIN' | 'USER'`); missing/expired → 401, forbidden → 403.
- Error JSON shape everywhere: `{ "error": { "code": string, "message": string } }`.
- Dependencies (exact, user approval required before Task 1 — CLAUDE.md "no new dependencies without asking"):
  - server: `express@5.1.0 @prisma/client@6.19.0 zod@3.24.2 jsonwebtoken@9.0.2 bcryptjs@3.0.2 cookie-parser@1.4.7 dotenv@16.4.7`; dev: `prisma@6.19.0 typescript@5.7.3 tsx@4.19.2 vitest@3.0.5 supertest@7.0.0 @types/express@5.0.0 @types/jsonwebtoken@9.0.7 @types/cookie-parser@1.4.8 @types/supertest@6.0.2 @types/node@22.10.5`
  - client: `react@18.3.1 react-dom@18.3.1 react-router-dom@6.28.1`; dev: `vite@6.0.7 @vitejs/plugin-react@4.3.4 typescript@5.7.3 tailwindcss@3.4.17 postcss@8.4.49 autoprefixer@10.4.20 @types/react@18.3.18 @types/react-dom@18.3.5`
- References: `SO-000001`, `PO-000001`, `MO-000001`, `BOM-000001`, `OP-000001` (6-digit zero-padded, per-prefix counter).
- Quantities `Decimal(12,3)`, money `Decimal(12,2)`. Services compute with `Prisma.Decimal`; the API serializes all decimals as JSON numbers.
- Commits small, conventional: `feat(sales): reserve stock on confirm`, ending with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- Ports: server 5000, client 5173.

## Review Focus

1. **Decimal quantities** (e.g. ordered 2.5, delivered 1.25 + 1.25): an order must flip to Fully Delivered exactly when delivered equals ordered; never compare with JS floats. → test in Task 11.
2. **Two operations confirmed at the same moment for the last units:** exactly one succeeds, the other gets 409 `INSUFFICIENT_STOCK`, on-hand ends at 0, never negative. → test in Task 11.
3. **Editing a confirmed order below what is delivered or pending:** rejected with 409 `QTY_BELOW_COMMITTED`, nothing changes. → test in Task 9.
4. **Cancelling an order that has placed (unconfirmed) operations:** those operations become REJECTED with reason "Order cancelled", reservations released, confirming them later returns 409. → test in Task 11.
5. **BoM edited after an MO was created from it:** the MO keeps its copied components and work orders (snapshot), so production consumes what the MO shows. → test in Task 8.
